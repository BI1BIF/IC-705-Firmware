# 日版 1.40：GPS 距离字段的简体中文回放

2026-11-14，Windows，官方日版 `705J140.dat`。把原厂的「距離:」改为「距离:」仅作用于 PC 仿真；在相同公制输入下，距离字节、数字和单位像素与日文原版一致。Icom 的 [1.40 更新公告](https://www.icom.co.jp/support/drivers/8603/)把 GPS 等页面使用米的上限从 1 km 提到 10 km；原厂代码在舍入到 10,000 米前切换单位。

| 模拟输入 | 原厂绘制文字（去除末尾填充空格） |
| ---: | --- |
| 5,000 米 | `5000m` |
| 9,999.4 米 | `9999m` |
| 9,999.5 米 | `10.0km` |
| 10,000 米 | `10.0km` |
| 无有效距离 | `-----km` |

原厂页面准备入口 `0x200B34B0` 在合成的第 2 页状态下，调用 `0x200B29D0`。有效记录时，`0x200748F8` 从 `0x203D9E30` 读取 0.1 米为单位的模拟距离；`0x200B2D10` 把它连同有效标志送进 `0x2021710C`，输出到 `0x204BACF2`。无效记录在同一调用点传入 `FFFFFFFF/0`。五组输出都与独立格式化测试一致；未推断 GPS 接收器协议或这个距离的上游计算来源。

原厂重画函数 `0x2018A8D0` 比较该位置和上一份状态的七字节：相同不重画，差一个字节就刷新该字段。其共用子程序 `0x20189500` 从 `0x2032AFBC` 取英语 `DST:`，从后一条记录取日语「距離:」，然后分两次调用文字绘制入口 `0x20142698`：一次画标签，另一次画七字节数值。回放直接记录两次绘制传入的地址和字节；旁边的速度标签也由原厂画出。

PC 词表只在显示／系统语言为 `02/01` 时给这一处距离标签提供文案。原厂显示状态只有一位，沿用第三语言预览的日语兼容方式；只改模拟的显示位，不写设置值或系统语言位。原厂字库已有「距」，缺「离」；只在内存追加一个开源 Noto 字形，并为这一条词添加实验编码映射。原厂字符转换、字形查询和渲染照常运行，数字没有经过词表。对照结果：

- 五组中文像素差异都局限于 `[113,165,129,182)`，恰是换字区域。数字和单位位置不变；在两条边界输入上，中文标签右侧与数值至少有 6 像素间距。
- 分别从模拟存储重载日语 `01/01` 和英语 `00/01`，在两个边界上均与各自原版逐像素一致。英语系统 `02/00` 与原版 `00/00` 一致。故意不加载「离」时，PC 实验保留日语标签，图像与原版日语一致。触摸切换与保存见[既有第三语言回放](IC705_ZH_THIRD_LANGUAGE.md)。

置信度高，限于回放的公制距离和指定绘制路径。输出是原厂局部绘制在软件画布上的结果；当前未从 GPS 菜单完整进入、未运行完整冷启动，也未证实原厂能自行加载中文词表。后续已[跑通 GPS 输入和 `0x203D9E30` 的原厂写入](IC705_GPS_INPUTS.md)，区分了实时定位、UTC 和对方台站记录。

## 复现

```powershell
$env:PYTHONPATH = (Resolve-Path .analysis/ic705-emulator/deps).Path
py -3.14 -X utf8 -m tools.replay_705_gps_distance firmware/705J140.dat .analysis/ic705-emulator/j140-gps-distance
```

复用项目现有的 Unicorn 与 Noto 来源。输出 `gps-distance.json`、两条边界的日英中文与缺字对照 PNG，以及从中文绘制结果截取放大的 `gps-distance-detail.png`。两次输出逐文件相同，36 项测试通过。原厂 DAT 哈希不变；没有连接设备或生成更新包。[REA 证据范围](REA_ANALYSIS.md#j140-gps-距离文字与绘制)。
