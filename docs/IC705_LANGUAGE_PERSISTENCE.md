# 日版 IC-705 1.40：显示语言保存、重载与第三语言卡点

2026-11-13，Windows 离线实验。日版原厂 `705J140.dat` 在 PC 上已跑通「日语 → 英语 → 保存 → 新实例重读 → 日语 → 保存 → 新实例重读」。显示语言切换只写显示语言字段，系统语言两次重读均为日语。原厂保存和读取代码可以原样保存第三值 `2`；原厂选择菜单和界面状态无法把它作为独立语言使用。

样本来自 [Icom 日本 1.40 发布页](https://www.icom.co.jp/support/drivers/8603/)。[日版手册](https://www.icom.co.jp/support/manual/4873/)印刷页 13-19 分别定义「表示言語」和「システム言語」。样本 SHA-256 为 `2522f62211ad5fdb313e793f94bb0574a22327660bdbde47ba9124f424114e45`，解包后主程序为 `d25971deae61ab0db52ed80338516119367887728da6e67a29d05710aceac4a9`。运行地址按[已验证的装载映射](MAIN_CPU_DECODE.md)解释，字节由 [REA](REA_ANALYSIS.md#j140-语言保存与重载)复核。

| 实验 | 显示语言 / 系统语言 | 实测结果 |
| --- | --- | --- |
| 原厂选择器 | `01 / 01` | 只有「英語」「日本語」。点击第三行坐标时，触区报告 `0x40`，但无菜单状态变化、无语言字段写入、无存储请求，重绘仍为两项。 |
| 点击英语，暂不保存 | `00 / 01`（模拟 RAM） | 原厂立即显示 `Display Language: English` / `System Language: Japanese`。此时新实例从旧存储重读，仍为 `01 / 01`。 |
| 保存英语，重读 | `00 / 01` | 原厂读回英语显示和日语系统；重读后的显示设置第 6 页与保存前英文画面逐像素一致。 |
| 切回日语，保存并重读 | `01 / 01` | 原厂恢复日文页面，「表示言語」「システム言語」都显示「日本語」。 |
| 独立实验：仅在 RAM 注入显示值 `02`，保存并重读 | `02 / 01` | 原厂存取保留 `02`；有效语言函数也返回 `2`。随后页面打包丢掉其高位，标题和标签用英语，当前值却显示「英語」，暴露了两套路径对第三值的处理不一致。 |
| 独立对照：系统语言英语 | `02 / 00` | 原厂有效语言函数返回 `0`；页面为英语且隐藏 `Display Language`，仅保留 `System Language: English`。该对照使用单独的合成存储，与正常切换不共享写入。 |

## 原厂代码与模拟边界

- 原厂触摸轮询与菜单动作最终由 `0x200A29C0` 向 `0x203EAE44` 写一个字节。`0x203EAE45` 没有收到选择动作的写入。`0x203806F7` 的 `0x40` 是重绘请求：原厂在 `0x2009651C` 测试它，更新程序在 `0x20095DE8` 清除它。点击时没有同步写存储。
- `0x202DE844` 是 5 条设置分区的描述表。第三条将 RAM `0x203EAA49`、比较副本 `0x20396EFB`、逻辑存储起点 `0x392C0` 和长度 `0x1099` 配对。显示语言在逻辑地址 `0x396BB`，系统语言在 `0x396BC`；这些是设置存储地址，和 DAT 文件偏移无关。
- 运行原厂保存入口 `0x2004E938`，由 `0x2004E820` 比较活动设置与副本并向底层发送变更。三次保存均观察到针对显示语言地址的单字节写入，系统语言字节均未变化。原厂周期路径在 `0x200D512C` 调用 `0x2004E820`；本实验显式调用同步入口，未测真实调度和写入时机。导航可能更新其他设置字节，所有变更偏移均在 JSON 中记录。
- 每次重新加载都用新建的 ARM 实例；先把其 RAM 内两个语言值设为 `FE/FE`，再运行原厂读取入口 `0x2004E73C`。该例程发出 714 个只读请求；其中逻辑 `0x396A0` 的 32 字节读入 `0x203EAE29`，覆盖两个偏好字段。固件再建立设置副本。常规切换从触摸开始；仅第三值和英语系统负对照用合成初值。
- Unicorn 执行原厂 ARM 指令。宿主仅在 `0x2005E4C8`（读取）和 `0x2005E554`（写入）用内存模拟逻辑存储，不模拟它们以下的 EEPROM 总线、设备时序或整机冷启动。设置写入只发生在模拟器内。没有访问电台，也未生成更新文件。

## 原厂基准之后的第三项试验

[独立第三项续测](IC705_ZH_THIRD_LANGUAGE.md)已在 PC 模拟 RAM 中完成点选、保存、重载及日英与系统语言回归。下面是原厂基准给出的三个设计约束。

1. 两个原厂语言记录 `0xA7` / `0xA8` 都限定 `0–1`，并共享 `0x202ED520` 的选项表。先在模拟器里给**显示语言**单独做三项选择，保留**系统语言**的原表和原判定。
2. 界面同步时，`0x20095E94` 的 `BFI` 只把显示语言最低一位写入 `0x204BAB65` 的 bit 1；`0x20095EA4` 把系统语言写入 bit 0。因此英语 `0` 和候选 `2` 都打包为 `01`（系统日语），日语 `1` 则为 `11`。绘制入口 `0x201549B4` 的常规文字选择器 `0x20179F8C` 也把非零显示值归为同一索引：按原调用的 `R2=0` 和日语系统独立执行，输入 `0/1/2` 返回 `0/1/1`。因此不能只改状态位；还需让第三值独立到达页面标题、选项标签与当前值路径，同时保留原有系统语言位和英语系统隐藏规则。
3. 接入[已有的 ARM 中文词表与字库](IC705_ZH_CATALOG.md)，让它只在显示语言为 `2` 时工作。先验证第三项可点、选中值正确、保存后重读仍为中文、日英画面与系统语言对照通过，再考虑整机词表。仿真中的资源传入方式不代表原厂固件已提供安装或加载接口。

## 复现

使用现有项目虚拟环境和[可选 Unicorn 依赖](IC705_EMULATION.md#复现)，从项目根目录运行：

```powershell
$env:PYTHONPATH = (Resolve-Path .analysis/ic705-emulator/deps).Path
.\.venv\Scripts\python.exe -m tools.replay_705_language_storage firmware/705J140.dat --out .analysis/j140-language-persistence/replay
```

输出为 7 张原厂绘制的 PNG 和 `language-storage.json`（含语言写入、读写请求、存储差异、画面文字和 SHA-256）。两次独立运行的对应文件 SHA-256 全部一致。现有 `unittest` 套件 36 项通过；该真实样本回放需本地合法取得的 DAT，单独运行。
