# 日版 1.40：原厂 GPS 输入、UTC 与距离缓存

原厂 ARM 代码已在电脑上跑通：逐字节接收合成 NMEA → 发布本机经纬度和 UTC → 用接收台站坐标计算距离 → 把结果写进原厂 RX 页的距离文字。**定位有效与 UTC 有效分别判断；过期的经纬度仍能被读到，甚至还能算出距离。** 这条链给本机卫星跟踪提供了 GPS 输入依据。原厂 RX 距离是对方台站到本机的地表距离，语义见 [Icom 英文活用手册](https://icomuk.co.uk/files/icom/PDF/advancedManuals/IC-705_ENG_Advanced_4.pdf)的 GPS Position → RX；它不提供卫星斜距或径向速度。

## 数据从哪里来

样本是 [Icom 日版 1.40](https://www.icom.co.jp/support/drivers/8603/)；DAT SHA-256 `2522f62211ad5fdb313e793f94bb0574a22327660bdbde47ba9124f424114e45`，解出的 Cortex-A9 主程序 SHA-256 `d25971deae61ab0db52ed80338516119367887728da6e67a29d05710aceac4a9`，装入地址 `0x20005000`。下面的地址只对应这个版本。

| 数据 | 原厂代码和数据 | 证据 |
| --- | --- | --- |
| GPS 字节入口 | `0x202055B4` 从环形缓冲取字节，在 `0x20205614` 调 `0x20212A34`。后者接收以 `$` 起始、CRLF 结束的报文，调 `0x202122B0` 分发。 | 前段是静态调用证据；回放从逐字节入口开始，未模拟串口中断。 |
| 本机坐标 | RMC 经 `0x20211CAC` 和发布分支 `0x2021258C`，写 `0x205DC90C`（9 字节纬度）和 `0x205DC915`（10 字节经度）。读取函数分别是 `0x20212B20`、`0x20212B40`。 | 在实时 GPS 模式回放确认 `3530.0000,N / 13930.0000,E` 读成 `35300000N / 139300000E`。 |
| 本机 UTC | RMC 路径 `0x20211B2C`；ZDA 路径 `0x20212174`。`0x20212B80` 读取 `DDMMYY`（`0x205DC8EC`），`0x20212B64` 读取 `HHMMSS`（`0x205DC8F2`）。 | 从初始化开始，第 3 条连续有效 RMC 首次发布 UTC；随后 ZDA 跨过午夜，由 `14-11-2026 23:59:59` 更新至 `15-11-2026 00:00:00`。 |
| 定位与 UTC 标志 | `0x203813D1` 的 bit 2 是实时定位标志（`0x20212BC8`），bit 3 是 UTC 标志（`0x2021300C`）。`0x20074650` 在 GPS Select = ON 时取实时定位标志，OFF 恒为 0，Manual 恒为 1。 | 回放 GPS Select = ON；三模式分支见反汇编，模式值与 [Icom CI-V 指南](https://www.icomeurope.com/wp-content/uploads/2020/08/IC-705_ENG_CI-V_1_20200721.pdf)的 `1A 05 0281` 一致。 |
| 3D 与高度 | GSA 驱动定位维度（`0x20212FC0`）；GGA 高度经 `0x20211D30`，在 `0x20212BD8` 更新后由 `0x20212CDC` 读出。 | 先输入 3D GSA，再输入高度 123.4 m 的 GGA，读得内部值 4049（符合英尺的百分之一取整）；GPS 丢定位后仍可读到上次的 3D，不能拿维度代替有效标志。尚未校验高度基准转换。 |
| 对方台站和距离 | `0x20073DF4` 用 `0x2021A6AC` 检查选中记录；表基址 `0x205DDDC8`、步长 `0x70`、坐标偏移 `+0x0D / +0x16`，有效字节在 `0x203813EE + 索引`。`0x20228DE8` 收到对方纬经与本机纬经，随后 `0x20073EEC` 写距离缓存 `0x203D9E30`。`0x200B34B0` 准备页面，`0x2021710C` 格式化到 `0x204BACF2`。 | 合成对方记录写入 RAM；原厂代码计算及格式化全程不替换。具体 LCD 绘制见[上一轮对照](IC705_ZH_GPS_DISTANCE.md)。 |

## 离线验收

| 场景 | 缓存或状态 | 原厂 RX 页 |
| --- | --- | --- |
| 同坐标／北移一分／东移一分 | `0 / 18522 / 15079` 分米，后两项与独立球面参考的差值均小于 5 m | `0m / 1852m / 1508m` |
| 对方记录无效 | 原厂不进入几何计算，写 `0xFFFFFFFF` | `-----km` |
| RMC、ZDA 校验错误 | 已发布的坐标、时间、有效标志和两个倒计时均不变 | — |
| 合法 `V`（无定位）RMC | 初始化后不会创建定位；已有定位时，旧值与当前倒计时保留，倒计时不刷新 | 在原厂定位过期前仍显示 `1852m` |
| 本机定位过期、对方记录仍有效 | 实时定位标志清零；经纬度和 3D 仍可读取，重新计算仍写 `18522` 分米；UTC 仍有效 | `-----km`，页面拒用旧距离 |
| UTC 过期；随后恢复 | UTC 标志清零，时间与日期变空格。有效 RMC 可先恢复定位，ZDA 再独立恢复 UTC；只让 UTC 过期也不会清掉定位。 | 新本机坐标与对方相同，恢复到 `0m` |

定位、UTC 倒计时分别在 `0x2038130E`、`0x20381310`，本回放观察到刷新值是 120。后续 J140、E140 原厂计时回放每 4,000 次 IRQ 159 将定位倒计时减一，同期弹窗计时增加 250；以原厂默认 2,500 格／10 秒换算，定位缓存约 120 秒到期。归零到 GPS 任务执行过期处理之间，有效标志仍可能为 1。两版过期后的原坐标仍可读。本次未在实体机上计时。卫星补偿宜同时检查实时定位、UTC 和各自更新年龄；固定台址可作为单独的手动模式，仍需可信 UTC。[双版 IRQ 回放](../.analysis/aprs-fix-age/stock-timing.json) · [Icom 弹窗计时说明](https://www.icomeurope.com/wp-content/uploads/2024/06/IC-705_ENG_IM_Basic_7.pdf)

## 复现

```powershell
$env:PYTHONPATH = (Resolve-Path .analysis/ic705-emulator/deps).Path
py -3.14 -X utf8 -m tools.replay_705_gps_inputs firmware/705J140.dat .analysis/ic705-emulator/j140-gps-inputs/gps-inputs.json
```

[回放工具](../tools/replay_705_gps_inputs.py)校验原厂 DAT 和主程序哈希，调用项目原有只读解包器；输出包含报文、状态快照及计算函数实际收到的坐标。[REA 证据](REA_ANALYSIS.md#j140-gps-输入与距离缓存)复核样本及窗口，GNU objdump 和 Unicorn 分别用于查调用关系与验证运行。静态摘录在同一输出目录。两次回放的 JSON 逐字节一致，项目 36 项测试通过。未连接电台、未更改原厂 DAT，未生成刷机文件。

[固定轨道的桌面回放](IC705_SATELLITE_PASS.md)已接入本例程和[原厂 VFO/Split 回读](IC705_VFO_SPLIT.md)，证实失去任一有效标志都立即停止给出补偿。仍待确认的 GPS 细节有实际计时、数据更新的一致读法、硬件接收路径和高度基准；这些与整机启动、原厂资源加载、可部署固件的门槛分别验收。
