# D5 CW 固件内测审核

2026-11-18。对象是日版 41 系列 IC-705、1.40 的 D5 CW 接收测试包。用户本次反馈是“测试正常，掉帧的现象好了一点点，目前看还是稍有掉帧现象，但是整体上来看没有太大的问题”。这作为真机结果记录；未给出测试时长、实体帧率或逐字参考正文，不另推断所有专项均已验收。

**结论：D5 已具备实际使用的内测基础，但还不能按稳定完成版结项。** 本轮确认两项解码缺口：默认 WIDE 对部分音调漏收；AUTO 在训练后长静默的前史下更容易把干扰当成文字。轻微掉帧仍有用户实测反证。受测路径没有发现新的崩溃、写越界、退出后旧译文回写或错误封装；这不代表原厂整个固件已被完整还原、全部功能都无缺陷。

本轮只审计当前交付件及其与原厂采音、任务、绘图、按键的衔接。未改生产代码、未重新编译/打包、未重测已通过的升级/开机、未连接或操作电台。新增脚本只向本次审计目录写证据。

## 已确认问题

### 1. 优先修复：默认 WIDE 的音调覆盖比右窗所示范围小

**触发及影响：** 打开 CW DECODE 后，滤波默认是 `WIDE`。该检测器只有约 450–850 Hz 的九个探测点；右窗频谱显示 300–1250 Hz，AUTO 也能跟踪这个更宽的范围。因而可能出现“波形和频谱明显有声音，但译文一直空白”。这是译码选音的支持差异，不是采音再次断开。

**验证：** 同一精确 D5 工作线程、同样干净的 20 WPM `CQ TEST`：

| 音频音调 | WIDE | FILTER AUTO |
| --- | --- | --- |
| 300 Hz | 无文字 | `CQ TEST` |
| 600 Hz | `CQ TEST` | 本轮未重复 |
| 1000 Hz | 无文字 | `CQ TEST` |
| 1250 Hz | 无文字 | `CQ TEST` |

这些是特定输入点，不据此把 450–850 Hz 宣称为有严格截止边界的模拟带通。也不意味着原厂 CW 音调设置覆盖表内每一个测试频率。

**定位：** [默认档及会话](../samples/cw-j140-lab.c#L22)、[退出重置](../samples/cw-j140-lab.c#L542)、[进入回调](../samples/cw-j140-lab.c#L594)、[WIDE 译码调用](../samples/cw-j140-lab.c#L864)；[九点检测器](../samples/cw-arm.c#L222)；[频谱范围](../samples/cw-audio-spectrum.h#L19)。

**最小解决方向：** 先明确界面中 WIDE 的当前覆盖，另行验收默认改为 AUTO 或跟随原厂 CW 音调；若扩大 WIDE 检测点，需同时复核干扰误报和开销。当前可在底栏第 2 页 `ADJ → FILTER → AUTO` 选择已支持的自动选音；标题的速度 AUTO 与这里的 FILTER AUTO 是两项不同设置。

**如果暂缓：** 用户在某些音调下仍会漏掉整段干净来报。不能以 600 Hz 已通过代替整个音调范围通过。

证据：[解码子报告](../.analysis/cw-audit-d5-1118/decoder/REPORT.md)、[逐字输出](../.analysis/cw-audit-d5-1118/decoder/targeted-evidence.json)。可信度：高，限精确 D5 局部机器码及给定输入。

### 2. 优先修复：AUTO 训练后长静默，抑制干扰误字的能力减弱

**触发及影响：** `FILTER AUTO + 自动速度 + 自动门限` 已正常收过报，之后长时间无信号，再来同频道噪声/干扰。译码器仍保留已训练状态，首次确认来报所用的较严格门限不再生效，容易继续抄出伪文字。不是 D5 显示优化新引入的回归，也不代表所有静默都会出字。

**验证：** 用真实的合成 PCM 正常解出 `CQ TEST`，再输入额外 10 秒零 PCM；随后送入已有人工标注无可辨 CW 来报的 `noise7405.wav` 前 30 秒。未训练对照用等长零 PCM 前缀，噪声起点和分块相位完全相同：

| 前史 | 同一 30 秒噪声的非空白误字数 |
| --- | ---: |
| 等长静默，尚未训练 | 0 |
| 正常解出 `CQ TEST`，再静默 10 秒 | 15 |
| 保留上一行全部滤波/选音历史，仅在噪声前诊断性清译码状态 | 0 |

噪声 WAV SHA-256：`a861d73b77ae2cecb532b656e79ff9468bb581effedfc74edca91a1677756631`，原文件帧 `[0,240000)`。训练后噪声前 `trained=LIVE / age=1000 / tracked_hz=300`。逐字事件、音频摘要和诊断控制均保留；从冷启偏移零开始的“2 误字”因分块相位不同只作次要对照，主结论采用表内同相位的 0→15。

**定位：** [仅初始状态清理](../samples/cw-arm.c#L281)、[首次确认门限](../samples/cw-arm.c#L393)、[按初始状态选择门限](../samples/cw-arm.c#L430)、[只在明显换音时重置](../samples/cw-j140-lab.c#L850)。

**最小解决方向：** 为长时间无有效载音增加重新确认来报的状态，保留速度作为先验。不能简单整体提高门限或随意清状态；新规则必须同时验收长停顿后短应答、弱台和同频续收，避免用漏抄换少乱码。尚未实现新规则或选定安全超时。

**如果暂缓：** 长期开着 AUTO 接收时，短片段无来报测试的误字数可能低估实际使用中的误报。长按 CLR 当前只清文字，不能当作已验证的重新锁定办法。

证据：[解码子报告](../.analysis/cw-audit-d5-1118/decoder/REPORT.md)、[同相位对照及诊断控制](../.analysis/cw-audit-d5-1118/decoder/targeted-evidence.json)。可信度：高，限所用干扰片段和局部 ARM 工作线程；不是新的实体机准确率测量。

### 3. 已知性能问题：仍有轻微掉帧

**触发及影响：** 开 CW 后，上方频谱/S 表与右侧两个小窗不如关闭时流畅。用户对 D5 的最新评价是略有改善、仍稍有掉帧，整体没有明显大问题；该反馈不能标为“帧率已恢复”。

**现有解释：** D5 已减少双窗光栅计算，但每次相关绘图仍有整面板及双窗共 140,160 字节的逻辑像素上传，以及按钮/译文字形工作。80 ms 是普通双窗重新生成的门限，不是电台屏幕统一帧率。局部指令下降不能换算成整机 CPU 占用，也不能据此断言是硬件算不动解码。

**最小解决方向：** 分别测量译码工作与面板绘制/上传的实际预算；优先检查未变化面板、按钮和历史译文的重复工作。跨帧缓存必须处理原厂画布所有权、两个 LCD 缓冲和弹窗裁剪，不能为提速撤掉已解决撕裂的缓存清理与同步。本轮没有修改这些路径。

**如果暂缓：** 保留当前轻微不流畅的体验；本轮没有证据证明因此丢了采音或收发功能。物理帧率及最差调度余量尚未量化。

证据：[用户反馈](../.analysis/cw-audit-d5-1118/field-d5.json)、[D5 既有性能边界](IC705_CW_DISPLAY.md#d5-四行译文与绘图优化)、[当前绘图调用](../samples/cw-j140-lab.c#L1314)。可信度：用户可见现象高；各模块实际占用比例尚未测量。

## 工程追溯缺口

交付件及最终主程序摘要一致，没有发现本次打错包。原厂主程序范围内的 49 个差异字节全部落在预期的 14 处四字节补丁，原厂 277 条选择器记录逐字节保留。追加代码/表末端 `0x20373c22`，早于原厂数据边界 `0x20380000`，间隔 50,142 字节；这个静态间隔不是可继续随意使用的 RAM 承诺。引导和其余组件的保留结论沿用已完成的独立静态读回，没有重跑更新或开机。

**缺口：** 当前导出验收的 `source_sha256` 固定了主 C、入口汇编和像素表，但未纳入三个实际编译输入：`cw-arm.c`、`cw-audio-spectrum.h`、`cw-j140-rtx.s`。因此，未来复现构建时，单看这三项现有源摘要不足以识别全部依赖是否漂移。

**最小处置：** 下次构建清单记录全部六个传递输入、编译器版本及完整构建选项。本轮补存六项当前摘要，保留原交付快照，不能把今天的源摘要补写成历史构建证明。这是后续交付的可复现性问题，不是已证明当前 DAT 内容有误。

证据：[包及补丁审计](../.analysis/cw-audit-d5-1118/package-audit.json)、[复现脚本](../.analysis/cw-audit-d5-1118/audit_package.py)、[导出器源指纹检查](../.analysis/cw-smooth-1118/export-dat.py#L28)。可信度：高，静态检查。

## 功能边界与尚缺的验收

以下分开记录，不一律当成已发生的 bug：

- **译码准确率仍有边界。** 已有自然弱台留出样本在采用短衰落修复后仍有 12/20 字符编辑错误；特定 ARRL 练习样本 0/670 不能覆盖这种场景。不规则手键、极短空隙、自动估速突变和同频重叠仍会漏抄/错抄。[既有评分](CW_BASELINE.md#短衰落修复和独立录音验收)本轮没有全量重跑，不冒充 D5 全新测量。需要目标机录音与独立参考正文才能报实体准确率。
- **字符集尚非完整国际符号集。** 当前支持 A–Z、0–9 和九个标点；`+ @ ( ) ! ; _ &` 等会变成 `~`。本轮精确 ARM 对照确认，属于已实现范围的缺项；若要补齐，码表、字宽、字体与四行布局必须一起核对。用户已明确不需要和文，不应重新加入日文解码。
- **会话设置未持久保存。** 当前 CW 的接收配色/调整只在会话内有效，退出重开会复位。这是当前测试版范围，不是原厂显示语言/系统语言丢失；不能将其描述为已有断电保存功能。
- **本阶段只做接收。** 灰色 `TX MEM` 没有接通发射功能；不在本次已同意的接收目标内。CW 接收扩展没有替代原厂 KEYER/RTTY，也不等于取得完整原厂源代码。
- **KEYER 偶发点多次才进入、提示音的专项真机反馈未单独量化。** 电脑路径通过，用户最新整体反馈正常，但不能凭这一句话把这两项历史偶发现象宣称已逐项彻底修复。
- **仍缺目标机连续长时和组合验收。** 长时接收、反复开关页面、录音/瀑布/侧栏并用、实际收发恢复等尚无成套计时及内存记录。本轮没有发现相应新故障；缺验证不是故障已发生。
- **没有扩大安装或恢复结论。** 当前 DAT 保留原厂引导，未加入 SQ6EMM 的手动 A/B；日版 41 系列不依赖正常开机的独立恢复仍未验收，见[已有恢复记录](SAFETY_AND_RECOVERY.md)。这不是要求重复已通过的升级/开机，也不是本轮新发现的阻塞。

## 下一次修改的建议顺序

1. 先把默认选音覆盖及其界面说明处理清楚，避免出现有声无字。
2. 再修 AUTO 长静默后的来报重新确认；同一轮必须比较干扰误字和弱台/短应答漏字，不能只优化误报数字。
3. 保持原厂提交和缓存同步，继续减少重复绘图；用实体对比收尾残余卡顿。
4. 冻结功能，补完整构建清单，再做约定时长的连续接收及常用组合操作验收。

本轮输出是审计报告和证据，没有新固件需要用户重新刷入。D5 交付字节保持不变。
