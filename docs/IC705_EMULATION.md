# 在 PC 上运行日版 IC-705 原厂主程序

2026-11-13，Windows x64。已用 Unicorn 2.1.4 的 Cortex-A9 模型运行日版 1.32 和 1.40 的原厂机器码。**日版 1.40 已在 PC 上走通[原厂主屏、两页 `MENU`、`SET`、显示设置和返回](#日版-140原厂主屏与-menu)。** 可以在模拟内存里把菜单切成英文再切回日文，系统语言始终为日语。PC 提供按键与触摸采样、任务交接和软件绘图；原厂 ARM 代码执行输入、导航和绘制。VDC5 实际输出和整机冷启动仍待复现。[简体样页](IC705_ZH_CN_PAGE.md)只用于字库和排版。

Icom 日版 [1.32](https://www.icom.co.jp/support/drivers/7074/) / [1.40](https://www.icom.co.jp/support/drivers/8603/) 的输入哈希见[来源清单](../research/705j-provenance.json)；执行前校验[主程序与引导镜像哈希](MAIN_CPU_DECODE.md#原先的卡点与提取证据)。复用 REA MCP 的镜像核验和 GNU objdump 的地址映射。Unicorn 只装在项目忽略目录；没有改 REA 或 Codex 配置，也没有访问任何设备、串口或实际 Flash。公开的 [QEMU Arm 机器列表](https://www.qemu.org/docs/master/system/target-arm.html)和 [Renode 板卡文档](https://renode.readthedocs.io/en/latest/introduction/supported-boards.html)未找到可直接使用的 705 板卡模型；后者的列表也明确不完整。通用 Cortex-A9 板不能提供该电台的外围硬件模型，换成 Linux 不会补上这一层。

## 原厂菜单行和 GPS 函数的动态证据

给隔离的原厂函数提供语言状态和 `0xA7` 菜单记录，记录原厂代码发给文字绘制入口的参数，再运行原厂文字转换。这里使用合成的调用环境，未启动设置页面；即使可见性函数返回隐藏，也单独调用行函数以观察原厂标签。日英切换和隐藏是两个独立断言。

| 系统语言 | 显示语言设置 | 固件判定该行 | 单独调用行函数时原厂标签 |
| --- | --- | --- | --- |
| 英语 | 英语 | 隐藏 | `Display Language` |
| 英语 | 日语 | 隐藏 | `Display Language` |
| 日语 | 英语 | 可见 | `Display Language` |
| 日语 | 日语 | 可见 | `表示言語` |

两版提交相同的文字样式 `1`、局部坐标 `(10, 23)`，日语原文为 `95 5C 8E A6 8C BE 8C EA`，转换以 `U+8868` 开头。局部坐标不是 LCD 的绝对坐标；这项两版对照在文字绘制入口记录参数并返回。J140 可见性入口 `0x2009FE30`，行函数 `0x2014B548`，绘制请求 `0x2014B630 → 0x20142698`；J132 对应 `0x2009E920`、`0x20147E2C`、`0x20147F14 → 0x2013EF7C`。字库及「表」的独立轮廓对照见[语言链报告](IC705_LANGUAGE_FONT.md)。

另用原厂公制距离格式化函数作版本对照：输入 `5000 m`，J132 实际返回 `5.0km`，J140 返回 `5000m`。两版的 `500 m`、`12000 m` 和无效数据都分别返回 `500m`、`12.0km`、`-----km`。这组行为由 ARM 机器码产生；没有模拟 GPS 接收机。

## 日版 1.40：原厂菜单行像素

使用 [原厂菜单行复现脚本](../tools/render_705_stock_row.py)。按 SHA-256 限定 J140 主程序和字体 `font-0.ttf`，将字体挂在虚拟只读 Flash `0x18C00000`，在模拟 RAM 中提供字体位置、两个原厂语言状态和合成的第 0 行 `0xA7` 记录。原厂 `0x20195190` 返回绘图面为 `480 × 272`，原厂 `0x20144F00` 初始化内置 FreeType，行函数调用原厂字节转换、字体查找和 OpenVG 文字绘制。日文「表」由原厂程序转换为 `U+8868`，FreeType 返回字形索引 `3136`；其余三字依次为 `1893、1541、1585`。原厂选用 18 像素字体、黑色画笔，并给出四字的轮廓与各自的 18 像素前进量。日文和英文无需电脑上的日文或英文字体。

| 系统语言 / 显示语言 | 原厂输出 | PNG 非透明范围 `[x0,y0,x1,y1)` / 像素数 |
| --- | --- | --- |
| 日语 / 日语 | `表示言語` | `[11,33,83,50)` / 792 |
| 日语 / 英语 | `Display Language` | `[13,33,179,54)` / 1244 |
| 英语 / 日语 | 隐藏，未提交绘图 | 无 / 0 |

第二个实验使用 `--language-pair` 调用原厂封装 `0x2014BA80`，以 `0xA7`、`0xA8` 两个合成的可见行记录为输入。封装从真实设置表读取两项各自的当前值。两项分别用独立的原厂语言状态；PC 并不提供标签或右侧文本。下表列出从 OpenVG 绘图命令复核的四种状态。

| 系统语言 / 显示语言 | 第一项：标签 / 当前值 | 第二项：标签 / 当前值 |
| --- | --- | --- |
| 日语 / 日语 | `表示言語` / `日本語` | `システム言語` / `日本語` |
| 日语 / 英语 | `Display Language` / `English` | `System Language` / `Japanese` |
| 英语 / 日语 | 隐藏 | `System Language` / `English` |
| 英语 / 英语 | 隐藏 | `System Language` / `English` |

PC 提供少量内存管理和图形环境调用；收到原厂 `vgAppendPathData`、`vgSetGlyphToPath` 和 `vgDrawGlyphs` 后，按实际平移、画笔和轮廓进行软件填充。PNG 是透明文字层；本地预览裁切并放大原始输出，灰底用来同时看清原厂的黑字和白字。这个模型没有实现 GPU 的自动微调或 VDC5 输出，行位置来自合成的调用环境，页面标题、背景、装饰和高亮没有合成，所以坐标和抗锯齿仍不能与真机截图逐像素对比。切换状态由实验写入模拟 RAM，并非通过点击菜单。两版的既有实验通过，J140 四个状态从官方 DAT 重新提取后输出的 PNG 和绘图记录逐字节一致。

REA MCP 对原厂字体的独立复核证据为 `ev_f16fcd5b733620adfcb1e22d3cfd3b3405bad23cb1b5b1f54055eaaf2ce7090a`。原始 OpenVG 记录、像素范围和每张 PNG 的 SHA-256 由脚本写入 `trace.json`；所有像素和提取物都留在 Git 忽略目录。

## 日版 1.40：显示设置整页画面

[页面复现脚本](../tools/render_705_display.py)直接读取原厂 `705J140.dat`，校验 SHA-256，解包主程序、原厂字体和图形资源。沿原厂调用链得到三项新证据：

1. **菜单顺序由固件生成。** `SET` 的子项引用 `67`，标题表索引为 `67−22=45`，原厂标题是 `ディスプレイ設定` / `DISPLAY`。实验将显示分类索引 `36` 和标题编号 `67` 写入模拟 RAM，原厂 `0x200A163C` 从 `0x20301544` 起的子项表生成可见列表；原厂 `0x200AD034` 再按当前页首项与光标生成四个行槽。日语系统有 22 个可见条目，英语系统有 21 个；显示语言 `0xA7` 被原厂列表生成器移除，系统语言 `0xA8` 保留。这次无需手工写入行记录、文字、分页计数或排版。
2. **页面例程绘出整帧。** 在界面状态 `0x0C` 下，直接调用原厂 `0x201549B4`，实际进入标题 `0x20153D5C`、选项封装 `0x2014BA80` 等函数。第一次在 `0x20145420` 读取原厂位图头 `0x18A51AA4` 时停住；根据固件原有的 `+0x5F0000` 资源重定位，将解码后 A 组前 `0x600000` 字节映射至虚拟只读 `0x185F0000`。这一映射上的位图头、宽高、步幅和像素由固件自己的代码读取。主程序和字体沿用既有映射；这里确认的是界面所访问资源的别名，不是整机 Flash 布局。
3. **同一个模型复现选中样式。** 电脑按原厂 OpenVG 请求填充矩形、绘制字形以及裁切、复制和缩放位图。两个日语末页实验只改变模拟光标，`(200,40)` 和 `(200,100)` 两处的蓝色 `#5DA0C9` 与黑色随选择对换；两项文字不变。首帧输出 12 条清屏矩形和 18 条位图绘制，日语末页各 14 条和 16 条。全部 `480 × 272` 像素不透明，未垫桌面背景。

| 本地输出（`.analysis/ic705-emulator/j140-display-stock/`） | 复核内容 |
| --- | --- |
| `01-display-first-jp.png` | `1/6`、LCD 背光和三条原厂项目，带原厂滑条、分页箭头及返回键；背光 `0%` 等数值来自模拟 RAM 初态，不是出厂默认。 |
| `06-display-language-jp.png` / `06-system-language-jp.png` | `6/6`、两项日语语言设置，分别高亮第一行和第二行。 |
| `06-display-english.png` | 英文标题；`Display Language: English` 与 `System Language: Japanese` 分开显示。 |
| `06-system-english.png` | 英文标题；只显示 `System Language: English`。 |

独立重新解包、执行两次，五张 PNG 与 `trace.json` 的 SHA-256 完全一致。图形资源切片 SHA-256 为 `61ce95358f7ca0710a445a3070ec95fdfaad4afeb4343a3cbc756cd6e54778e0`。REA 对应主程序页例程字节证据 `ev_5fc9269ac6b4bb40277a746c3da7667c621699309e47c7bbe738b4300ddbc4c0`；用 GNU objdump 确认代码入口，用 Unicorn 记录实际调用。Icom 日版手册印刷页 `13-19` 核对了两项设置的正式名称和语义。这五个基准帧的初始值和光标由脚本设定；下节另用原厂例程产生页首和光标。位图最近邻采样及字形抗锯齿为 PC 软件实现，尚无同版本真机 PNG 可逐像素比对。

## 日版 1.40：原厂设置导航重放

[导航重放脚本](../tools/replay_705_settings.py)读取并验证原始 `705J140.dat`，复用上节的图形映射。初始语言状态均设为日语。脚本调用原厂菜单入口打开 `SET`；其后的页首、菜单编号、选中项、栈和绘图模式由固件自己写入。每一步记录原厂写入指令地址、写入值、画出的文字和 PNG 的 SHA-256。

| 实验 | PC 提供的输入 | 原厂行为和观察结果 |
| --- | --- | --- |
| 双向翻页 | 把下一页 `0x17E` 或上一页 `0x17D` 交给原厂分派器 `0x2007D360` | 原厂表 `0x202E2A08` 指向翻页回调 `0x2008B670` / `0x2008B668`，由 `0x200A2EE4` 更新列表状态。显示设置依次画出 `1/6` 至 `6/6`；末页再次向下返回 `2`，画面哈希不变。最后向上回到 `5/6`。 |
| 打开两个语言子菜单 | 在 `SET 2/4` 或显示设置 `6/6` 提供已命中的行号，进入原厂行回调 `0x2008B548` | 两项共用通用菜单 `286`，但分别绘制标题 `表示言語` 和 `システム言語`，各有 `英語`、`日本語` 两项。返回 `6/6` 时分别恢复第 1、2 行的高亮。实验只打开选项，不提交语言变更。 |
| 返回上层 | 调用原厂返回回调 `0x20089DA0` | `0x200F0954 → 0x200F022C` 弹出菜单栈并恢复光标。即使离开显示设置的页面与进入时不同，仍回到 `SET 2/4` 并高亮第 4 行 `ディスプレイ設定`。 |

原厂 `0x20095DBC` 更新页面，并调用 `0x200AD034` 构建原厂行。末尾 `0x2008F700` 交给 UI 任务；在未模拟 RTX 的情况下继续运行会触及 `SVC`（`0x202D47F4`）。脚本在这个边界接手调度，随即执行原厂绘制分派器 `0x2015ADDC` 和列表渲染器 `0x201549B4`。这条路径验证原厂导航与绘图，但没有运行原厂触摸坐标命中、返回事件来源、任务调度或 VDC5。初始设置也不代表出厂默认值。

两次独立解包和执行产生的 15 张 PNG 与 `trace.json` 全部逐字节一致。本机输出在 `.analysis/ic705-emulator/j140-settings-replay/`。REA 复核了分派器、回调、返回和 UI 更新的原始字节；GNU objdump 的静态路径与 Unicorn 动态写入一致。[REA 证据索引](REA_ANALYSIS.md#j140-原厂设置导航)给出复核编号。

## 日版 1.40：用鼠标操作原厂设置

Windows 双击项目根目录的 [Open-IC705-Panel.cmd](../Open-IC705-Panel.cmd)。在主屏点窗口下方 `MENU`，再点第一屏菜单右下的 `SET`。从 `セット 1/4` 点右边向下箭头，再点第四行「ディスプレイ設定」，继续向下到 `6/6`。点第一行「表示言語」，再点「英語」；同页应显示 `Display Language: English` 和 `System Language: Japanese`。进入 `Display Language` 并选 `Japanese` 即可切回日语。「重置」丢弃当前模拟内存。遇到未建模的页面、访存或绘图分支时窗口会暂停，可重置。

宿主把坐标写入原厂采样缓冲 `0x203E1F23`（状态字节、两个大端 16 位坐标），用一次按下、两次释放轮询调用原厂 `0x2007F104`。固件 `0x20108550` 解码样本，`0x201083B0` 按菜单状态选择触区表，`0x20107418` 对照表里的矩形。`0x201088F4` 把触区换成事件和行号；原厂分派和延后回调按自身逻辑完成操作。鼠标处理不提供事件编号、行号、页首、返回回调或语言值。已验证的动作：

| 像素坐标（左上为原点） | 原厂触区 → 事件 | 结果 |
| --- | --- | --- |
| `(449,163)` / `(449,69)` | `0x23 → 0x17E` / `0x22 → 0x17D` | 向下／向上翻页。 |
| `(120,230)`，`SET 2/4` | `0x21 → 0x17C` | 选择第 4 行，打开显示设置。 |
| `(120,54)` / `(120,119)`，显示设置 `6/6` | `0x1E / 0x1F → 0x17C` | 分别打开显示语言和系统语言。 |
| 同样两个坐标，显示语言子页 | `0x3E / 0x3F → 0x184` | 选择英语或日语。原厂 `0x200A29C0` 只写显示语言字节 `0x203EAE44`；系统语言 `0x203EAE45` 始终为 `01`，没有被写入。 |
| `(449,244)` | 通用语言子页 `0x44`，显示设置 `0x24`，均 → `0x38` | 原厂触发同一个返回回调；返回父页时恢复选中行。 |
| `(22,8)` | `0`，无事件 | 点标题无动作，前后画面哈希一致。 |

`--replay` 保存 17 张原厂界面帧和 `trace.json`。两次独立重放的全部输出逐字节一致。另在真实 Windows Tk 窗口发送鼠标点击，核对窗口尺寸、切换后的画面和返回高亮。动态证据仅覆盖模拟 RAM 和软件图形输出；未模拟触控硬件、长按／拖动、RTX 调度及电台设置的持久化。实验没有连接电台，没有改动 DAT 或写入实际存储。REA 的独立字节复核见[触摸证据索引](REA_ANALYSIS.md#j140-触摸坐标与语言提交)。

## 日版 1.40：原厂主屏与 MENU

窗口的 `MENU` 按钮只改变原厂按键采样缓冲 `0x203E1F1C` 的第 3 位。每个按下或释放阶段调用原厂 `0x2007F104` 七次，覆盖七组采样。`0x2007F010` 识别物理键号 `5`，`0x2007D6C0` 经原厂表分派事件 `0x44`，`0x200872E8` 打开 `MENU`。按键处理由固件执行，窗口不直接选页。以下为实际回放结果：

| 操作 | 触区与事件 | 原厂状态 |
| --- | --- | --- |
| 主屏按 `MENU` | 按键事件 `0x44` | 显示模式 `2`，菜单第 1 页。 |
| 点底部 `2` / `1` | `0x1BB` / `0x1BA`，均为 `0x46` | 第 2 页、再回第 1 页；重返第 1 页画面哈希一致。 |
| 第 1 页点右下角 `SET` | `0x1B9 → 0x45` | `0x20087340` 经延后回调打开原厂菜单 `22`。 |
| `SET 2/4` 点显示设置 | `0x21 → 0x17C` | 原厂打开菜单 `67`。两项语言的选择器用显示模式 `13`。 |
| 从显示设置连续点返回 | `0x24 → 0x38` | 返回 `SET 2/4`，恢复第 4 行高亮；再回主屏。 |
| 重新打开 `MENU` 后点返回 | `0x1BC → 0x38` | 回主屏，两次返回的主屏均与初始主屏像素一致。 |

模拟器验证并挂载两份原厂字体，通过 `0x20145244` 初始化字体实例。在原有任务交接点执行外层原厂绘图分派 `0x2013C5E8`：主屏 `0x201636F8`，菜单格 `0x2013D82C`，设置列表 `0x2015ADDC`。按 `0x20195190` 所读的原厂表区分 LCD 和离屏绘图面，并复现原厂像素搬运：菜单与设置由第 18 号 `480 × 272` 绘图面合成；主屏经第 11 号 `480 × 149` 绘图面把上方区域合入 LCD。OpenVG 观察路径增加 `VG_A_8` 和 `VG_sRGB_565` 输入；离屏软件合成保留 RGBA，不模拟实际 GPU 的 RGB565 量化。独立 REA 字节证据见 [J140 主屏与 MENU](REA_ANALYSIS.md#j140-主屏与-menu)。

与 [Icom 日版手册](https://www.icom.co.jp/support/manual/4873/) 印刷页 `2-6` 对照，第 1 页十个图标、页码和返回键的位置一致。第 2 页已画出 `GPS`、`PICTURE`、`PRESET` 等图标，但当前离线状态的 `DTMF` 灰显、右下 `SET` 未出现。手册说明菜单随操作模式而变；尚未用真机验证此差异的具体条件。主屏频率是零，底部没有实时频谱，画面上的状态标记只反映本次模拟 RAM。未把手册截图用作面板背景。

`--panel-replay` 保存 25 张 `480 × 272` PNG 和一份 `trace.json`。两次独立重放的 26 个文件逐字节一致；在 Windows Tk 窗口通过 `MENU` 按钮和真实的 Tk 鼠标事件重放，25 帧解码后的像素全部一致。原 `--replay` 的 17 帧与轨迹文件仍与本轮前的基线逐字节一致。样片和轨迹留在 `.analysis/ic705-emulator/j140-front-panel/`，未加入 Git。未访问实体电台或修改 DAT。

| --- | --- | --- |
| 从 Flash 引导镜像 `0x18000000` | 4 条指令后，在 `0x18000094` 向 `0x3FFFFF80` 写 `1` | 该地址用途未确认；没有提供芯片 Boot ROM 或完整 Flash。 |
| 从预装入 SRAM 的主程序 `0x20005000` | 26 条指令后，首次向 `0xFCFE1A10` 写 `0x0F000F0F` | Renesas 手册表 5.6、§5.10.5：`AXIBUSCTL3` 控制 OpenVG 图形处理器的总线缓存行为。 |
| 同一主程序，提供 AXI 寄存器模型 | 两版写入 `AXIBUSCTL3–8`，第 24,107 条指令尝试读 `0xE8201000`；J140 PC `0x20124378`，J132 PC `0x20120D3C` | Renesas 手册表 7.2：这是中断分发器 `ICDDCR`。AXI 模型只记录写入和读回；无缓存、GPU、LCD、中断或定时功能。 |

依据：[Renesas RZ/A1H 硬件手册 R01UH0403EJ](https://www.renesas.com/en/document/mah/rza1h-group-rza1m-group-users-manual-hardware)、[Renesas VDC5 参考实现](https://www.renesas.com/en/document/apn/rza1h-group-qe-video-display-controller-5-sample-program)、[Khronos OpenVG](https://registry.khronos.org/OpenVG/specs/openvg-1.1.pdf)。停点是虚拟板缺少外设时的实际访存，不是对真机的运行结果。遇到未知地址直接停，不给整页外设填零以求继续。

## 第一屏的验收

1. **从单行扩展到整页。** [单行实验](IC705_ZH_NATIVE.md)已验证原厂显示设置可用独立的内存字体画出「显示语言」，日英切换仍有效。下一步验证多条资源、选项值和参数占位符，另核对 VDC5 通道、帧地址、行距和像素格式。
2. **用实物参考对照。** 已核对 [Icom 日版手册](https://www.icom.co.jp/support/manual/4873/)印刷页 `2-6` 的实际 MENU、FUNCTION、快捷菜单画面，`13-19` 的「表示言語／システム言語」语义，以及 `14-4` 的 microSD 截屏。若已有日版 1.40 的 `ディスプレイ設定` 第 1 页和第 6 页原始 PNG，按相同高亮和设置状态作像素对照；手册截图只做布局与操作参考。
3. **启动和整机能力分开。** 启动链继续按手册实现实际触及的 GIC 寄存器，再跟踪定时器、时钟及必要的存储和输入。页面验证可以先使用受控状态，无须先模拟 RF、FPGA 和 DSP。之后逐步纳入 CW、SSTV、FT8、选星与多普勒的界面回归；接收音频、实时性、收发切换、升级和恢复仍须独立验证。仿真通过只能作为真机测试前的一道检查，不能证明更新包可安全刷入。

## 复现

在项目根目录运行。Unicorn 是可选依赖；原有扫描脚本不依赖它。若已有同名提取目录，使用新目录或跳过对应提取步骤。

```powershell
py -3.14 -m pip install --only-binary=:all: --target .analysis/ic705-emulator/deps unicorn==2.1.4
$env:PYTHONPATH = (Resolve-Path .analysis/ic705-emulator/deps).Path
py -3.14 -X utf8 -m tools.render_705_display firmware/705J140.dat .analysis/ic705-emulator/repro-display-page
py -3.14 -X utf8 -m tools.replay_705_settings firmware/705J140.dat .analysis/ic705-emulator/repro-settings-navigation
py -3.14 -X utf8 -m tools.virtual_705_panel firmware/705J140.dat --replay .analysis/ic705-emulator/repro-settings-touch
py -3.14 -X utf8 -m tools.virtual_705_panel firmware/705J140.dat --panel-replay .analysis/ic705-emulator/repro-front-panel
foreach ($version in '705J132','705J140') {
    $outDir = ".analysis/ic705-emulator/repro/$version"
    py -3.14 -m tools.decode_705_main "firmware/$version.dat" $outDir
    if ($LASTEXITCODE -ne 0) { throw "Firmware extraction failed: $version" }
    $report = py -3.14 -X utf8 tools/emulate_705.py $outDir
    if ($LASTEXITCODE -ne 0) { throw "Emulation failed: $version" }
    $report | Set-Content -Encoding utf8 ".analysis/ic705-emulator/$version.json"
}
py -3.14 -m tools.probe_705_fonts firmware/705J140.dat --extract-to .analysis/ic705-emulator/repro/j140-fonts
py -3.14 -X utf8 -m tools.render_705_stock_row `
    .analysis/ic705-emulator/repro/705J140/main.bin `
    .analysis/ic705-emulator/repro/j140-fonts/font-0.ttf `
    .analysis/ic705-emulator/repro/j140-stock-language --language-pair
```

脚本限制每次运行的指令数和时间。原有双版本脚本校验四组语言和四组 GPS 结果；新脚本校验两项的可见性、标签及右侧值、日文「表」的字形索引和输出像素。去掉 `--language-pair` 并换用新输出目录可复现只绘制左侧标签的早期实验。复现实验保存在本机 `.analysis/ic705-emulator/`。代码、报告可以保留；固件、切片和手册只用于本地对照。
