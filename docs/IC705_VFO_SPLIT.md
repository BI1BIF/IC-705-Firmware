# 日版 IC-705 1.40：双 VFO 与 Split 离线回放

2026-11-14。验收目标是在电脑上验证 A/B 选择与 Split 开关的四种组合，分别读出接收频率、另一个 VFO 的频率及发射候选频率。**四组均通过；再切回 A，读数恢复到初始值。** 未连接电台、执行 PTT、写入实机或生成刷机包。

## 四组实测

把 145.900 MHz 和 436.850 MHz 两个合成值放进 Unicorn 的来宾 RAM，再调用原厂 A/B 选择与 Split 例程。下表是原厂返回的数值；频率单位为 MHz。

| 当前 VFO | Split | 接收 `03` / `25 00` | 另一个 VFO `25 01` | 发射候选 `1C 03` | 原厂面板副频文本 |
| --- | --- | ---: | ---: | ---: | --- |
| A | 关 | 145.900 | 436.850 | 145.900 | 空白 |
| A | 开 | 145.900 | 436.850 | 436.850 | `436.850.00` |
| B | 开 | 436.850 | 145.900 | 145.900 | `145.900.00` |
| B | 关 | 436.850 | 145.900 | 436.850 | 空白 |

每组的 `0F` 与 Split 设置一致，`1C 00` 都返回 `00`（接收）。同一来宾先在 Split 开启时由 A 切到 B，再关闭 Split，最后切回 A；脚本逐项对比首尾的原厂回复。向与来宾地址不符的 `A5` 送入 `03`，原厂收帧代码不置就绪标志，分派器也不产生回复。`25 00`/`01` 是相对于当前 VFO 的选择；规划上下行时应同时核对 `0F` 和 `1C 03`，不能直接把 `25 01` 当成上行。

## 原厂路径与证据

输入为 [Icom 日版 1.40](https://www.icom.co.jp/support/drivers/8603/) `705J140.dat`，SHA-256 `2522f62211ad5fdb313e793f94bb0574a22327660bdbde47ba9124f424114e45`。从该包解出的主程序 SHA-256 为 `d25971deae61ab0db52ed80338516119367887728da6e67a29d05710aceac4a9`，装载于 `0x20005000`。地址只对应 J140。

| 观察点 | J140 地址与行为 |
| --- | --- |
| CI-V 收帧和分派 | `0x20029F94` 按字节处理本地请求；目的地址与 `0x203EAAD6` 核对。`0x2001B988` 读取邮箱并调用 `0x2001B73C`；后者使用 `0x202DA920` 和 `0x202DAA68` 两级表。`0x20388673+0x83` 返回应答正文，后续传输代码 `0x2002AE74` 才加上 `FE FE`。 |
| 选 A/B | `0x2001DEA8` 和 `0x2001DEBC` 是 `07 00`/`07 01` 对应的原厂处理入口。实验直接调用它们以建立状态，不从 CI-V 送写帧。选 B 后，两条工作记录 `0x203EBC2E+1/+37` 的次序确实互换；回到 A 时恢复。 |
| 接收与 VFO 读数 | `03` 的 `0x20024FE4` 取当前工作频率缓存；`25` 的 `0x200280D4` 根据选择字节取当前缓存或另一个工作记录，返回五字节 BCD。 |
| Split 与发射候选 | `0x20103914` 建立 Split 状态；`0F` 回读 `0x200250C4`，`1C 03` 回读 `0x20026604` → `0x201031DC`。普通 VFO 模式中，`0x2002EAFC` 的结果决定发射候选读工作记录 `+1` 还是 `+37`。 |
| 面板对照 | 主屏更新在 `0x2009608C` 调用 `0x20094AB0`。该入口独立于 CI-V 分派；Split 开时经 `0x200948AC` 调用同一个频率选择函数，再格式化面板副频字段 `0x204BABB9`（模式字节及后续 11 字节文本）。Split 关时该字段清空。本次验收的是原厂面板文本，未绘制这一字段的像素。 |

[Icom CI-V 指南](https://www.icomeurope.com/wp-content/uploads/2020/08/IC-705_ENG_CI-V_1_20200721.pdf)第 3、14、16、26 页提供命令语义和 BCD 格式；[Icom 基本手册](https://www.icomeurope.com/wp-content/uploads/2024/06/IC-705_ENG_IM_Basic_7.pdf)第 4-10、4-11 页说明原厂 Split 操作，示例为同频段。**可信度高，限指定 J140 例程和普通 VFO/接收状态。** 两个跨段方向均能形成正确的逻辑候选；这不能证明实机能在这两个方向发射，也未覆盖存储信道、DR、中继偏移或发射中的更新。

## 复现

使用现有 Windows Python、Unicorn 与已下载的日版包。从项目根目录运行：

```powershell
$env:PYTHONPATH = (Resolve-Path .analysis/ic705-emulator/deps).Path
py -3.14 -X utf8 -m tools.replay_705_vfo_split firmware/705J140.dat .analysis/ic705-emulator/j140-vfo-split/replay.json
```

脚本先核对 DAT 与主程序 SHA-256，再断言四组读数、A/B 回切、接收状态、错误目的地址和面板文本。JSON 记录每组原始请求与原厂应答正文；本机两次输出的 SHA-256 都是 `017e003186e4fb8abb9130c3e081cc1a718a44f87b56a0f8261ae9fbc39ec582`，现有 36 项单元测试也通过。Windows [REA MCP 证据](REA_ANALYSIS.md#j140-ci-v-与-vfosplit)复核了主程序哈希和代码窗口；GNU objdump 复核调用，Unicorn 验证实际分支及数据。整个验证无需增加 Provider 或使用 WSL。

[离线过境回放](IC705_SATELLITE_PASS.md)已采用上述原厂角色、GPS 和 UTC 输出，验证两种跨段方向的双路多普勒补偿和失效停更。调谐写入及实体 RF 另行验证。
