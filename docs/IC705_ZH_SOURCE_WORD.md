# 日版 1.40：在原厂字符转换前加载一条中文菜单文案

2026-11-14，Windows，日版 `705J140.dat`。从原厂「表示言語」的取字指令接入一条 PC 词表，在原厂字符转换、字形查询及 OpenVG 绘制路径上显示「显示语言」。用同一份已保存的中文偏好重建仿真实例，改后的词表能显示「界面语言」。这是离线验证的接入位置；没有发现原厂会自行从文件加载词表。

| 对照 | 实际结果 |
| --- | --- |
| 原厂转换器 `0x20144CAC`，仅更换输入编码 | 「显示语言」的 UTF-8、GB18030 输入均不能得到正确文字；标准 CP932 编码不收录「显」和「语」。两组实验字节 `F5 F0`、`F5 F1` 在原厂转换器下落到 Unicode 私用区，因此实验映射仅对该条词表输入启用。 |
| 接入位置：`0xA7` 的日语标签指针 `0x202F0E2C` | 原厂取字分支 `0x2014B41C` 原先读到 `0x2035CAE0`。只在显示/系统语言为 `02/01` 时把该条数据读取指向模拟资源，随后由原厂代码测量字节长度并转换。`0xA8` 和原厂词表不变。 |
| 原厂解码指令，扩大两条字节映射 | 只对实验字符串使用原厂 79 项映射表的副本，加 `F5 F0 → U+663E`（显）和 `F5 F1 → U+8BED`（语）；「示、言、界、面」沿用原映射。模拟器没有写转换输出或渲染缓冲区。用原厂大字库的内存副本保留原字形及其度量，仅追加这两个 Noto 字形。 |
| 改词表及重载 | 启动时从本地 JSON 读取；运行中改文件，旧实例仍显示「显示语言」；新实例读取同一份设置和改后的文件，显示「界面语言」。变化在 480×272 图像的 `[11,33,47,50)` 内；原厂设置页其他文字、图块和系统语言不变。 |
| 切换、保存与系统语言 | 原厂触控回调 `0x200A29C0` 依次写入显示语言 `02 → 00 → 01`，原厂保存例程只在两项语言中的显示语言偏移 `0x396BB` 写 1 字节。每次从新实例用原厂例程重读设置。`01/01`、`00/01`、`02/00` 页面均与原厂对照逐像素一致；`02/01` 的系统语言选择页也一致，英语系统仍隐藏「显示语言」。 |

实验仅替换显示设置第六页的行标题。「Chinese」仍用前次实验的第三项占位标签，选择器标题及选项仍是原文字；不把它与之前的[六页显示设置汉化](IC705_ZH_CATALOG.md)混为一谈。四个旧的绘制后处理分支保持原厂指令。保留此前 PC 预览中把选项 `2` 暂按日语索引给原厂旧调用方的兼容处理。主程序、原厂字体和设置仅由电脑加载进仿真内存，未导出改过的原厂字体、刷机文件或设备写入指令。

[后续对照](IC705_ZH_RESOURCE_ORIGIN.md)已确认列表行名与选择器标题共用原厂指针、选项值另走一张表；早期内存初始化和原厂 ICF 导入都未写入这些资源。当前 PC 接入可继续验证文本和版式。全机冷启动、原生资源入口及其他功能按[路线图](../ROADMAP.md)独立推进。

## 复现

复用现有的 Unicorn、Arm GNU 工具链和 Noto 字体。脚本复制实验词表到输出目录，并在该副本上演示编辑；原始文件保持不变。

```powershell
$env:PYTHONPATH = (Resolve-Path .analysis/ic705-emulator/deps).Path
py -3.14 -X utf8 -m tools.replay_705_menu_word firmware/705J140.dat .analysis/ic705-emulator/j140-menu-word
```

输出包括 `menu-word.json`、两张中文对照和四组日英/系统语言对照。两次独立回放的 JSON 和 10 张 PNG 哈希分别一致；旧的第三语言回放记录也与基准一致，36 项测试通过。REA 的镜像窗口证据见[工具报告](REA_ANALYSIS.md#j140-转换前的菜单文案)。
