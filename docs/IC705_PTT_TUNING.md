# 日版 IC-705 1.40：双 VFO 调谐与 PTT 状态边界

2026-11-14。**原厂 ARM 在接收状态下能直接修改当前与未选中的两个 VFO，两个跨段方向都已回读并恢复。** 先前跨段写入被拒，是仿真未初始化频率范围表；补上原厂初始化后，无需临时切换 A/B。PTT 实验则区分了按键输入、请求应答和状态确认三个层次。只使用电脑与原厂 `705J140.dat`，没有打开电台连接、修改固件或验证射频。

## 双 VFO：失败原因和现在的结果

原厂 `25` 写入分派从 `0x200234A0` 进入；`0x20102C5C` 选择相对目标记录，随后 `0x2001D5D8` 调用 `0x2001CC04` 解析五字节 BCD 和校验频率。`0x2002E850` 查 `0x203DABD8` 中的范围表；返回值 bit 7 表示未匹配，`0x2001CC50` 检查这位。在空 RAM 中同一目标返回 `FA`、解析结果为 0，未进入 `0x20103BA0`，双 VFO 和 Split 的回读保持原值。加载地址 `0x20005000`，相关原始窗口见 [REA 记录](REA_ANALYSIS.md#j140-ptt-与双-vfo-调谐)。

随后在**同一个**来宾调用原厂 `0x20098B50`（原程序在 `0x20099104` 调用），由它从原厂表计算测试环境的频率分类。读出三段范围：30 kHz–29.999999 MHz、74.8–199.999999 MHz、400–470 MHz；这是本实验里的**接收调谐分类表**，不能当作发射许可、地区法规或整机灵敏度规格。未由宿主编造范围，也未跳过范围检查。再提交同一个目标，分类通过，原厂进入记录提交并返回 `FB`。原厂相对索引和请求语义与 [Icom CI-V 指南](https://www.icomeurope.com/wp-content/uploads/2020/08/IC-705_ENG_CI-V_1_20200721.pdf)一致。

| 选中 / Split | 初始 A / B（MHz） | 两路更新后 A / B（MHz） | `1C 03` 发射候选（MHz） |
| --- | --- | --- | --- |
| A / 开 | 145.900000 / 436.850000 | 145.903015 / 436.840972 | 436.840972 |
| B / 开 | 145.900000 / 436.850000 | 145.896985 / 436.859028 | 145.896985 |

每步核对 `03` 的频率缓存、`25 00` 和 `25 01`、`0F`、`1C 00` 与 `1C 03`，并与两组原厂 RAM 频率记录交叉验证。两次写入分别生效：第一笔完成时，第二路还是旧值；第二笔才更新发射候选。这两笔不是原子操作。逐笔恢复频率后，A/B 选择、Split 和全部检查值与初始一致。本实验只验证了频率恢复，未写入模式或亚音，也没有测接收机调谐时延。

## PTT：按下、松开与状态回读

| 层次 | J140 原厂证据 | 回放结果 |
| --- | --- | --- |
| 手咪输入采样 | `0x2010B948` 读两个模拟端口半字（`0xFCFE3204` 与 `0xFCFE3210`），后者 bit 13 是本分支的低有效输入。 | 松开 → 按下 → 保持 → 松开时，`0x203809C4` bit 0 为 `0 → 1 → 1 → 0`；最后 `0x203809C6` 的 bit 6 置位。两路频率、Split 和状态读数保持不变。端口来自仿真，未核对手咪原理图针脚。 |
| CI-V 请求 | `0x200225E4 → 0x2007F4E0` 写 `0x203806F4` bit 5，来源记录在 `0x20380703`。 | 两次按下请求和两次松开请求都返回 `FB`，bit 5 为 `1 → 1 → 0 → 0`，来源字节是 `02`。`1C 00` 始终为 `00`；`FB` 仅代表本次请求被受理。 |
| 收发状态公布 | `0x20109E74` 内的 `0x2010A084` 写 `0x203806F4` bit 7；`1C 00` 的 `0x200265C4` 读这一位。 | 依照任务中的顺序调用五个 PTT 例程，再运行状态函数，每阶段运行三轮。没有命中 bit 7 的写点，未重放从按键到实际状态确认的完整转换。 |
| 收发状态读端的对照 | `0x20103258` 在本场景中依 bit 7 选择接收或 `0x201031DC` 的发射候选。 | 单独向模拟 RAM 注入 `0 → 1 → 0`，`1C 00` 同步回读，频率选择函数按接收 → 发射候选 → 接收切换；两个方向都通过。`03` 此时仍读原接收缓存，`1C 03` 始终只读候选。正对照只验证读端。 |

**卫星补偿的直接结论：** UI 把「PTT 请求／按住」和「原厂状态回读」分开。补偿在检测到请求或按键时即冻结；退出恢复与继续调谐须等待已确认的接收边界，不以 `FB` 或候选频率代替确认。[后续 PC 选星页](IC705_SATELLITE_PANEL.md)已使用原厂 ARM 调谐后端，验证第二路拒绝、第一笔后触发冻结以及确认接收后继续或恢复。

后续 [CW 音频实验](IC705_RX_AUDIO.md#接收发射和静音的切换)补齐了两个原厂调用，从来宾 CI-V 请求重放到原厂发射与接收状态发布，无需直接改写状态位。手咪到状态发布、真机射频和机内菜单接入仍未验证。

## 复现

使用本机已有的 Windows Python、Unicorn、REA 和 GNU Arm objdump，无需 WSL、额外 Provider 或安装。DAT 和主程序 SHA-256 在脚本中固定，与 [VFO 读回报告](IC705_VFO_SPLIT.md)相同。从项目目录运行：

```powershell
$env:PYTHONPATH = (Resolve-Path .analysis/ic705-emulator/deps).Path
py -3.14 -X utf8 -m tools.replay_705_ptt_tune firmware/705J140.dat .analysis/ic705-emulator/j140-ptt-tune/new.json
```

脚本仅新建 JSON；本机 `.analysis/ic705-emulator/j140-ptt-tune/verified.json` 与独立重跑的 SHA-256 均为 `fdabc8de9a466ba401c746ce3d71f45041c385fedc5d8eaf4a6ca5ec03db53ea`。既有 VFO/Split 脚本重跑仍与此前报告逐字节一致。对指定原厂程序和测试场景的可信度高；不能外推到发射期间写频、软硬件收发时序或射频输出。
