# 日版 IC-705 整机简体中文化

**长期需求：在日版电台本机 LCD 上提供可选的「简体中文」界面，保留原厂日语、英语和操作功能。** 日版 1.32 和 1.40 已验证[显示语言到实际字形](IC705_LANGUAGE_FONT.md)的路径。日版 1.40 的[离线保存与重载](IC705_LANGUAGE_PERSISTENCE.md)证明存储可以保留第三值 `2`，但原厂选择器只有两项，界面状态也只保留一个显示语言位。原厂字符转换和日文字体仍缺部分简体字。主样本为 [705J140](JAPAN_FIRMWARE.md)。

[独立第三项](IC705_ZH_THIRD_LANGUAGE.md)已在日版 1.40 的 PC 仿真中通过点选、保存、重载及日英回归；系统语言的原厂选择器与隐藏规则保持原样。[词表回放](IC705_ZH_CATALOG.md)覆盖「显示设置」六页、对应选项和「显示单位」，并在「时间设置」复用同一字库。两项实验仍由 PC 将词表和字库装入模拟 RAM。

## 需求边界与验收

| 范围 | 验收 |
| --- | --- |
| 原厂本机界面 | 开机提示、主界面、快捷面板、全部设置、弹窗、错误、更新提示及 RTTY、存储、GPS、D-STAR 等功能页覆盖简体中文；固定在图片内的文字也纳入清单。 |
| 切换与回退 | 简体中文作为独立选项，保留日语、英语。切换后原厂配置和记忆保持原样，重启保持选择；缺失资源回退到可读语言，任何语言下均能找到切换入口。 |
| 排版与数据 | 在原厂显示尺寸验证无缺字、乱码、截断或重叠；频率、单位、数值格式、参数占位符、触控区和动态状态正确。呼号、模式名（CW、FT8、RTTY 等）、CI-V、文件数据和射频设置保持原有含义。 |
| 中文动态文字 | 单列验证频道名称、文件名和外部数据是否能正确显示和往返保存；不能用「静态菜单可显示」代替。中文输入法和中文语音播报是可选后续需求。机身印字不属固件范围。 |
| 新功能 | 后续 CW、SSTV、FT8 和卫星跟踪页面共用同一套术语和翻译规则；协议字段、呼号和接收内容按原样显示。 |

## 已核实的线索

- [Icom 日版手册](https://www.icom.co.jp/support/manual/4873/)第 13-19 页区分「表示言語」和「システム言語」。前者控制屏幕语言；后者影响可用字符。日语模式支持汉字、平假名、片假名及日文符号。[官方 CI-V 指南](https://www.icomeurope.com/wp-content/uploads/2020/08/IC-705_ENG_CI-V_1_20200721.pdf)的语言设置项 `0163`、`0164` 仅定义日语和英语。没有找到 Icom 公布的中文选项或语言包导入入口。
- 同一日版手册第 ii 页确认包含 **FreeType**；[GPS 和 RTTY 的共用绘制链](MAIN_CPU_DECODE.md#从距离字段到原厂文字绘制)核实主 CPU 内的字形诊断引用、OpenVG 参数与 Shift-JIS 型转换。后续提取的两份 TrueType 可与 FreeType 的实际加载参数对应。尚未证明全部菜单走同一分支。
- 早期在三个原始 DAT 扫描十个日英标签及常见字体标识均未命中。解开封装后，在两版日版主程序找到菜单标签，在 A 尾段找到两份字体。仅凭原始 DAT 扫描会漏掉这些资源。
- CP932 对照中，简体「频、设、发、单、储、确、认、复、蓝」无法编码。固件已确认把此菜单的 Shift-JIS 型字节转为 Unicode；CP932 可作对照，两者不一定完全相同。另有独立字库证据：原厂大字体没有「频、设、蓝、简」等字，仅替换菜单文字无法完成汉化。
- [CS-705 1.21/1.30 的静态对照](CS705_MENU_REFERENCE.md)找到了 Windows 程序中「表示言語」的 CP932 标签、`CL_Common_DispLang` 菜单键及主题 `54960.htm`。对应日英帮助跨版逐字节不变；两版原始 DAT 均未找到此标签或键的明文。这组数据能作菜单语义对照，仍不能用来确定电台字库编码或地址。
- [设置字段续测](CS705_SETTINGS_MAP.md)确认 PC 端显示语言与系统语言分别用一个字节，日版官方 ICF 为 `01/01`、美国版为 `00/00`，与 CI-V 的日英枚举一致。解包后的主程序另有可核对的两个独立 RAM 字段，位置见[语言报告](IC705_LANGUAGE_FONT.md#显示语言与系统语言)。

```powershell
.\.venv\Scripts\python.exe tools/probe_ui_resources.py firmware/705J140.dat firmware/705J132.dat firmware/705E140.dat
```

## 实施门槛

1. **绘制器已确认接收 16 位字符；上游仍受转换表约束。** 两版菜单绘制和缓存预加载的已识别调用均走原厂日文转换。系统语言与名称存储保留原厂语义。
2. **PC 单页已经验收。** [开放字体与回退对照](IC705_ZH_CN_PAGE.md)覆盖了 59 个字符、混排和参数占位符。简体子集 15,384 字节，故意缺字时以原厂字体绘制日英原文。整机字库预算要基于实际菜单词表另算。
3. **原厂绘制器的单行验证已通过。** [简体单行实验](IC705_ZH_NATIVE.md)在日版 1.40 的模拟内存里给原厂绘制器提供 UTF-16 和独立的内存字体，显示「显示语言」且没有改变原厂语言切换。现有[字体初始化](IC705_LANGUAGE_FONT.md#字体指针的来源)仍只证实内置 Flash 来源，未找到固件可直接导入的语言包。设备验证仍须通过[完整性与恢复门槛](SAFETY_AND_RECOVERY.md)。
4. **先验证第三项，再扩大翻译覆盖。** 在电脑上试点「日语／英语／简体中文」三项，检查选择后重载、原厂日英回退和系统语言字段隔离；模拟层通过不代表已找到原厂资源接入。词条索引、术语和参数占位规则可以同步整理，批量翻译按常用菜单、状态和错误提示、其余界面的顺序验收。

## 第一页验证：显示语言

**原厂行为。**入口是 `MENU → SET → Display`；系统语言为日语时才显示独立的「显示语言」项目。原厂 CI-V `1A / 05` 的选择器 `0163` 对应显示语言，`0164` 对应系统语言，`0161`、`0162` 是相邻单位设置。选择器是协议字段，不能直接当作固件资源 ID 或内存地址。

**固件与字体。**两版把显示语言和系统语言分别存储，显示语言决定标签指针，日文字体独立于这个文字索引选择。原厂「表」`95 5C → U+8868 → 字形 3136`；独立加载字体取得轮廓。「频、设、蓝、简」在原厂菜单转换表中无法表示，两份原厂字体也都无映射；本行绘制的未缓存路径查不到字形会退出。详见[地址、字体哈希与复现](IC705_LANGUAGE_FONT.md)。

**离线排版。**Icom [高级手册](https://icomuk.co.uk/files/icom/PDF/advancedManuals/IC-705_ENG_Advanced_5.pdf)列出的开机图规格为 480×272 px，本轮用它作参考画布。页面使用自制中文文案和 Windows Microsoft YaHei，未复用电台图形资源。渲染后人工检查 PNG；脚本另查字体 cmap 和实际字形边界。9 个文本框均无越界，59 个不同字符无缺字。最长说明行占 270 / 444 px；含 `145.500 MHz · CW` 的混排占约 207 / 444 px。故意送入未分配字符 U+0378 时，离线测试选择 English。此结果只验证桌面字体、文案和参考尺寸，不能证明机内有这些字形或能执行回退。

渲染输入是 [样张文本](../samples/zh-cn-display.json)。Windows PowerShell 运行：

```powershell
powershell.exe -NoProfile -STA -File tools/render_zh_cn_preview.ps1
```

该脚本输出早期 Windows 系统字体对照。后续使用指定的开放简体子集和两份原厂字库，生成[三张可复现样张](IC705_ZH_CN_PAGE.md)，完整结果见 `.analysis/zh-cn-preview/noto-page/metrics.json`。
